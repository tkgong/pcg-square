HEonGPU/GPU-NTT merge NTT vs the PCG^2 four-step (transposes on the DRU): structure from the code, per-N kernel time from silicon.

A. Global-memory passes per transform (from GPU-NTT's kernel table, src/include/gpuntt/ntt_merge/ntt.cuh, and fused4/):
   merge: tile = 512 or 1024 elements of shared memory (4-8 KB); passes = kernels per transform:
     logN 11-16: 2 | 17-26: 3 | 27-28: 4 (3 on the sm_89 build). Each pass reads+writes the whole polynomial (16N B on the GPU bus).
     The transpose is implicit: all passes but the last gather 64 B granules at a stride that grows with N
     (2^24: kernel 1 = 64 B every 1 MB, kernel 2 = 64 B every 8 KB, kernel 3 = contiguous 8 KB).
   four-step + DRU: the SMs only ever stream contiguous rows of length n1 or n2; the 2 transposes per transform run
     inside the DRAM on the DRU (full-row column ops, 16N B each on the bank-local path, 0 DQ bytes).
     SM passes per transform = kernels per sub-transform x 2:
       own fused kernel (fused4::Plan, 32 KB tile, n <= 2^12)      : 2 passes, N-independent (2^13 tile = 64 KB fits both cards -> 2^26; 2^14 = 128 KB fits B200 -> 2^28)
       GPU-NTT's own kernels (fused4g::PlanG, headline, a392780)  : row fixed at 2^10 (1 kernel) + column N/2^10 (2 kernels at 2^21-24) = 3 passes = merge's count
   per multiply (fwd a, fwd b, pointwise, inv): merge 9 passes + pointwise (168N B); headline four-step 9 SM passes + pointwise (144N B) + 6 DRU transposes (96N B in-DRAM);
   own-kernel four-step 6 SM passes + pointwise + 6 DRU transposes.

C. Kernel sequence per multiply at 2^24, batch 4, L40S (nsys, this machine, 2026-10-08):
   merge            : 9 x ForwardCore/InverseCore 1.93 ms each + pointwise 2.42 -> 19.8 ms per batch = 4.95 ms/mul
   headline four-step (a392780): 4 column kernels 1.58-1.64 ms + 2 row kernels (twiddle fused into the load) 2.41 + inverse row 2.39 + 2 column 1.58 + pointwise 2.42 -> 19.4 ms = 4.84 ms/mul;
                      the 6 transposes, if run on the SMs: 6 x 1.74 ms = 10.4 ms per batch = 2.61 ms/mul (35% of the all-on-SM time)
   own-kernel four-step: 2 x fwd_rows<pre> 2.36 + 2 x fwd_rows 1.71 + inv_rows<post> 2.32 + inv_rows 1.62 + pointwise 2.41 -> 14.5 ms = 3.63 ms/mul

D. Where the two designs stand as N grows (silicon, >= 2^22, geomean over batches):
   B200 merge / headline SM lane : 2^22 1.016, 2^23 1.019, 2^24 1.055  (the step at 2^24 is where GPU-NTT moves to 1024-element tiles and a 7+7+10 split)
   L40S merge / headline SM lane : 2^22 1.063, 2^23 1.077, 2^24 1.045
   L40S merge / own-kernel SM lane: 2^22 1.39, 2^23 1.36, 2^24 1.33
   Simulated NTT lane (ntt_vs_ntt, B200, DRU design vs merge, alone): 2^20 1.03, 2^21 1.01, 2^22 1.01, 2^23 1.02, 2^24 1.05.
   Merge's pass count is 3 over the whole measurable range (2^17-2^26), so the ratio cannot grow much inside it; the next structural step
   (4 passes) is at 2^27 in GPU-NTT's table. Sizes above 2^24 are not measurable here (prime 2-adicity; fused4 caps logN at 24).
