---- B2. Layout ablation: node-major (baseline) -> word-major ----
   BASELINE  node-major: one col holds complete words of a
     node. Each vector register needs 8 words scattered
     across 4 cols' 32b sub-slots; the column is the minimum
     access unit and the fixed PACKLR cannot compose an 8x4
     transpose -> per-word strided access, 4x rd+wr column
     traffic (cl unchanged). Measured: the extra traffic
     tips the loop past the 155-CK compute bound -- memory
     becomes the critical path (the bank-pair read/write
     split absorbs part of the 4x; the rest is exposed).
   DESIGN    word-major: storage view == register view
     (col j = word j of 8 seeds); VLD IS the transpose,
     0 permute ops, same hardware.
                     config |   ns/leaf | vs design | col traffic
      node-major (baseline) |    0.1140 |     1.17x | 4x (measured)
        word-major (design) |    0.0978 |     1.00x | 1x
   WHY: the SIMD lane axis IS the seed axis (QR ops are
   word-vs-word), so the register view is fixed by the
   compute; word-major makes the storage view identical --
   the layout, not the datapath, performs the transpose.
   Producer==consumer (children are emitted register-wise),
   so the convention sustains itself across all levels for
   free; only the final leaf->g scatter needs node order,
   and that is AGU address arithmetic, not data movement.
